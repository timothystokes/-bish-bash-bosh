# Planning

We need to define a concrete Plan of how we will do all the tasks required to implement the users objective. 

You will be asked to assess each specification item in a loop and for each one update the `.bish-bash-bosh/plan.md` file.

## The plan is a whole, not a log of specification items

The order the specification items arrive in means nothing: it is not a priority, a build order or a sequence of
work. The plan is a dependency graph that must be correct and coherent after every item. So each specification item
is a reason to reconsider the existing plan, not only to append to it: items already in the plan may need to change
(re-scoped, split, merged, given extra `S:` ids, re-timed, or given new `D:` dependencies), and a new item often has
to come before existing items that turn out to depend on it. Only the dependencies (`D:`) decide the build order.

## SPECIAL INSTRUCTION

When processing each item it is important to make sure that the tasks added ot updated are detailed and highly technical description of the work items to do.
