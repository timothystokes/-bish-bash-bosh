# Spec: Control, visibility, safety
- Autonomy: unattended or on-the-loop (visibility + controls). No per-step human gate.
- Terminal TUI first: live log tail, pause/resume/steer, kill switch, seconds and iterations vs budget. No Slack. Web dashboard is not in v1.
- Control channel: `control.json` (pause, resume, steer note injected into next stack, stop), read between iterations. Format `{paused?: boolean, stop?: boolean, steer?: string}`; missing file = running, malformed file = stop (fail closed); a steer note applies to one iteration then is removed; stop wins over pause; the file lives outside the target repo. Kill switch terminates the container. CLI: `hodgepodge control --file <f> pause|resume|stop|steer <note>` merges into the file atomically (refuses a malformed file); `podge --control <f>` enables it.
- Outer console (O-3, `src/inbox.js`): `hodgepodge console hodge|podge [--dir <sandbox>]` reads lines from stdin (no model, no run lock, so it runs beside a live loop) and appends each as a bullet to `<sandbox>/more-questions.md` (hodge) or `<sandbox>/more-todos.md` (podge), outside the target repo. `runInterview`/`runStep` (via `inboxDir`) add a `## More questions` / `## More todos` section to that prompt only (hodge: assess each and add it to the open questions; podge: end-of-session checklist adds each to `plan.md` before assessing the next best action), then remove exactly the entries sent, only after status `ok` (podge) or `ok`/`incomplete` (hodge), so failed or gated rounds retry them and entries typed meanwhile survive. `test/inbox.test.js`.
- TUI: `hodgepodge tui --control <f> [--dir <sandbox>] [--run-id]` redraws every second (`src/tui.js`): run state, seconds/iterations vs budget (flags OVER BUDGET), pending steer, declared formats, readiness per dimension per spec, QA cycles and findings, done evidence (`src/run-details.js`, read-only from the specs and `runs/<id>/done.json`, `qa-N/`), tail of the latest iteration transcript. Keys: `p` pause, `r` resume, `s` steer (Enter sends, Esc cancels), `x` stop (needs `y`), `q`/Ctrl-C quit. It only writes via `writeControl`. Kill switch is P3-5.
- Status-source abstraction (`src/status.js` `StatusSource` with `totals`, `lastStatus`, `tail`, `details`; `hodgepodge status [--dir <sandbox>] [--run-id] [--control <file>]` prints JSON iterations/seconds vs budgets and `details: {formats, readiness, qa, done}`): run files locally; execution status/history and CloudWatch logs in AWS.
- Secret scanning: small Node preflight-style proxy between agent and model (regex credential rules, redact to `[REDACTED:rule-id]`, nothing forwarded half-inspected, audit log). Implemented in `src/secret-proxy.js`: request and response bodies are buffered whole and redacted; over-limit body (413), upstream error or unwritable audit log (502) => blocked, never forwarded; audit JSONL (`{direction, target, findings:[{rule,count}], blocked?}`) never contains secret values. Metering: with `meterFile` (+ optional `rates`) each response carrying a token `usage` (OpenAI or Anthropic shape) appends `{time, tokens, cost}`; `readProxyUsage` sums it; unwritable meter => blocked. The proxy meter is a cross-check, not added to the budget gate (adapter usage is). Interview usage (`runs/<id>/interview/record.json`) counts in the run-wide budget via `sumRunUsage`. Run via `hodgepodge proxy --upstream <url> [--audit <f>] [--meter <f>] [--port <n>]` (prints `{port}`, serves on 127.0.0.1 until SIGINT/SIGTERM; no rates flag yet, so cost is metered as 0).
- Sandbox: Docker container per run locally; Fargate task in cloud.
- Audit log of tool calls.
