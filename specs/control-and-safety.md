# Spec: Control, visibility, safety
- Autonomy: unattended or on-the-loop (visibility + controls). No per-step human gate.
- Terminal TUI first: live log tail, pause/resume/steer, kill switch, seconds and iterations elapsed. No Slack. Web dashboard is not in v1.
- Control channel: `control.json` (pause, resume, steer note injected into next stack, stop), read between iterations. Format `{paused?: boolean, stop?: boolean, steer?: string}`; missing file = running, malformed file = stop (fail closed); a steer note applies to one iteration then is removed; stop wins over pause; the file lives outside the project repo. Kill switch terminates the container. CLI: `hodgepodge control --file <f> pause|resume|stop|steer <note>` merges into the file atomically (refuses a malformed file); `hodgepodge status`/`tui --control <f>` read it. Neither `gepo` nor `podge` accepts `--control`: the Plan Loop and Build Loop have no pause state, so there is nothing for it to act on (`specs/modes.md`).
- Outer console (O-3, `src/inbox.js`): `hodgepodge console hodge|podge` (operates on the current directory) reads lines from stdin (no model, no run lock, so it runs beside a live loop) and appends each as a bullet to `./more-questions.md` (hodge) or `./more-todos.md` (podge), outside the project repo's tracked content. Known gap: nothing currently consumes `more-todos.md` — the old build loop's inbox integration (`runStep`'s `inboxDir` option) was removed along with it, and neither `gepo` nor `podge` reads it yet; `more-questions.md` is likewise queued but not yet read by the Interview Loop. `test/inbox.test.js` covers only `addEntry`/`consumeInbox`/the console command itself, not loop consumption.
- TUI: `hodgepodge tui --control <f> [--run-id]` (operates on the current directory) redraws every second (`src/tui.js`): run state, seconds/iterations elapsed, pending steer, declared formats, readiness per dimension per spec, QA cycles and findings, done evidence (`src/run-details.js`, read-only from the specs and `runs/<id>/done.json`, `qa-N/` — see the status-source gap noted above: always empty for any run after the build loop removal), tail of the latest iteration transcript. Keys: `p` pause, `r` resume, `s` steer (Enter sends, Esc cancels), `x` stop (needs `y`), `q`/Ctrl-C quit. It only writes via `writeControl`. Kill switch is P3-5.
- Status-source abstraction (`src/status.js` `StatusSource` with `totals`, `lastStatus`, `tail`, `details`; `hodgepodge status [--run-id] [--control <file>]`, operating on the current directory, prints JSON iterations/seconds elapsed and `details: {formats, readiness, qa, done}`): run files locally; execution status/history and CloudWatch logs in AWS. `qa`/`done` are read off disk from `runs/<id>/{qa-N/, done.json}` (`src/run-details.js`) but nothing writes either any more since the old build loop's QA cycle and done-verification were removed with it — they are always empty/`null` for any run started after that removal, a known, structurally independent gap.
- Secret scanning: small Node preflight-style proxy between agent and model (regex credential rules, redact to `[REDACTED:rule-id]`, nothing forwarded half-inspected, audit log). Implemented in `src/secret-proxy.js`: request and response bodies are buffered whole and redacted; over-limit body (413), upstream error or unwritable audit log (502) => blocked, never forwarded; audit JSONL (`{direction, target, findings:[{rule,count}], blocked?}`) never contains secret values. Metering: with `meterFile` (+ optional `rates`) each response carrying a token `usage` (OpenAI or Anthropic shape) appends `{time, tokens, cost}`; `readProxyUsage` sums it; unwritable meter => blocked. The proxy meter is a cross-check, separate from adapter usage. Interview usage (`runs/<id>/interview/record.json`) is summed with other run usage via `sumRunUsage` (seconds only; there is no run-wide cap). Run via `hodgepodge proxy --upstream <url> [--audit <f>] [--meter <f>] [--port <n>]` (prints `{port}`, serves on 127.0.0.1 until SIGINT/SIGTERM; no rates flag yet, so cost is metered as 0).
- Isolation: Docker container per run locally, bind-mounting the project directory; Fargate task in cloud.
- Audit log of tool calls.
