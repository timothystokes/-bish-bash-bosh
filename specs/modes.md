# Spec: Modes (v1)
- **Interview:** conversation to `specs/*.md`, one spec per file; emits JSON Schema/OpenAPI where applicable.
- **Forward:** specs to code + tests (core loop).
- **Reverse:** code (and running system) to specs + characterization tests; specs aligned to standards (OpenAPI, JSON Schema, EBNF grammars, example-based conformance cases).
- **Brownfield:** spec delta to change; reverse first if specs are missing.
- **Test-hardening:** strengthen tests (mutation/property tests, coverage as gate).
- **Clean-room:** rebuild from the spec bundle only; the builder never sees the source (context firewall).
- Each mode has its own tuned loop prompt in `prompts/`.
- Every objective must define its tests; the harness refuses to start loops without them.
- Mode is selected by optional config key `mode` (default `forward`); a mode with no prompt file fails loudly.
- With config `requireTestPlan: true`, `hodge run` runs spec-lint before the first step and gates (no agent call) on any problem; each step then also applies the test-plan gate.
- `hodge interview [--dir <sandbox>]` takes no objective flag: the objective is asked for on stdin as the first answer of the interview (with an objective kit it is the same conversation as `hodge objective`; without one it is a single round). It runs the `interview` role (config must define it) with `prompts/interview.md` + both templates. It may only write under `specs/` and `tests/`; on agent failure, out-of-scope writes or any spec-lint problem the work is discarded (status `failed`). Records go to `runs/<id>/interview/` (not counted in run budget). Exit 0 only when ok.
- `hodge reverse [--dir <sandbox>]` runs the `reverse` role (config must define it) with `prompts/reverse.md` + both templates. It may only write under `specs/` and `tests/`; it is accepted only if spec-lint passes and the characterization suite (`npm test`, injectable) is green against the unchanged source. Otherwise the work is discarded (status `failed`). Records go to `runs/<id>/reverse/`. Exit 0 only when ok.
- With config `mode: brownfield`, `runStep` (and so `hodge step`/`hodge run`) is gated before any agent call unless `specs/` holds at least one `*.md`; the gate reason points at `hodge reverse`. The prompt (`prompts/brownfield.md`) tells the agent to write the spec delta first, then tests, then code.
- With config `mode: test-hardening`, `runStep` is gated before any agent call unless config `hardenCommand` (string array, e.g. a coverage or mutation-score command that exits non-zero below threshold) is set. After tests pass, `checkHardeningGate` (`src/hardening-gate.js`) runs it; non-zero exit => `failed`, work reverted. The agent may only change `tests/` (and `plan.md`): a `tests-only` scope gate rejects anything else. Prompt: `prompts/test-hardening.md`. record.json gates in this mode add `tests-only` (after anti-stub) and `hardening` (after types).
- `hodge clean-room --source <dir> --repo <builder-dir>` (`exportBundle`, `src/clean-room.js`) copies only `specs/` and `tests/` from the source into a fresh git repo with one root commit; it refuses a non-empty builder dir, source == builder, or a source lacking either directory. With config `mode: clean-room`, `runStep` is gated before any agent call by `checkCleanRoomGate` (firewall): the root commit may hold only `specs/`/`tests/`, specs and tests must exist, and (when given `sourceRemotes`) the builder must not have the source as a remote. Prompt: `prompts/clean-room.md`. The builder then runs the normal loop against the tests as the conformance suite.
- **Objective kit and requirements gathering** (`src/objective.js`, `src/readiness.js`, `templates/objective/`): `hodge init --seed objective` copies a general, solution-agnostic kit into the target's `objective/` (PHASES.md, INTERVIEW.md, READINESS.md, BRIEF.md placeholder, OPEN-QUESTIONS.md, CONVERSATION.md) plus a starter `plan.md`, adds an `interview` role to the config and sets `requireTestPlan`. `hodge objective --dir <d>` (role `interview`) asks the owner for a description of the objective (written to BRIEF.md), then alternates interview rounds with the owner's answers: stage `broad` until the first spec exists (rounds may only write `objective/`, status `incomplete`, no lint), then `fine`. Each round ends with the agent writing one next question to `objective/QUESTION.md`; the harness shows it, logs question and answer in CONVERSATION.md, commits, and starts the next round with the conversation, stage and current readiness gaps in the prompt. Ends `ok` when `checkReadiness` passes; an empty answer or EOF pauses (the pending question is re-asked on rerun), no question with gaps left is `stalled`, `--max-rounds` default 30 (`max-rounds`). Rounds record to `runs/<id>/interview[-N]/` and all count toward the run budget (`sumRunUsage`). Interview may also write `objective/` (notes, open questions, QUESTION.md). In kit mode `hodge interview` keeps a lint-clean, not-yet-ready round as status `incomplete`.
- **Readiness (when the conversation is enough):** `hodge ready [--dir|--repo]` prints `{ready, gaps}` from `checkReadiness`: spec-lint clean; per spec at least 3 requirements, each with exactly one "must", at least one example per two requirements, a failure/negative path, a non-empty Out of scope, no TBD/TODO/FIXME/`??`/`<angle>` placeholders outside code, mapped test files exist; and no unchecked items in `objective/OPEN-QUESTIONS.md`. `hodge run` is gated (no agent call) until ready whenever the target has `objective/`. `templates/objective/READINESS.md` mirrors the thresholds; change both together.
