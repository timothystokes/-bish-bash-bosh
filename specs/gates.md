# Spec: Gates (back-pressure, harness-enforced)
- Repo gate: refuse if target repo is hodgepodge.
- Test-plan gate: each objective needs `tests/PLAN.md` mapping specs to tests; tests must exist and **fail first** before build loops start. Agent-written tests alone do not satisfy the gate. Implemented in `src/test-plan-gate.js` (`checkTestPlanGate`): each line of PLAN.md names a `specs/*.md` path or a requirement ID (`R-<spec>-<n>`) and `tests/*` path; every spec must be mapped, mapped tests must exist, and the suite must be red before iteration 1 of a run. `runStep` option `requireTestPlan` gates (no writes) on failure.
- Type gate (`src/diff-gates.js` `checkTypeGate`): runs `tsc` in the target when it has a `tsconfig.json` (skipped otherwise; command injectable via `typeCommand`).
- Anti-stub gate (`checkAntiStubGate`): rejects TODO/FIXME/stub/placeholder/"not implemented" markers and empty function bodies on added lines of the diff (markdown files are not scanned).
- Scope gate (`checkScopeGate`): staged changes must sit inside config `allowedPaths` (directory-boundary match, `..` rejected); `plan.md` is always allowed.
- In `runStep` the scope and anti-stub gates run before tests; any failure => `failed`, work reverted. `record.json` gates, in order: repo, budget, scope, anti-stub, tests, types.
- Budget gate (`src/budget-gate.js`): tokens, cost, wall-clock and iteration caps per run, summed from run records (`usage.json`, incl. `seconds`). `runStep` refuses (`over-budget`, no sha, nothing written) when any cap is exhausted and gives the adapter only the remaining budget as limits.
- Fast-wheel rule: scoped tests per iteration; full suite on a schedule.
- Spec-lint (`src/spec-lint.js` `lintSpecs`, `hodgepodge spec-lint`): structure only. Each `specs/*.md` is non-empty, starts with `# Spec: <name>`, has one top-level title (one decision per file), titles are unique, and every spec is mapped in `tests/PLAN.md`. Requirement traceability (X-1): each spec has an `Implementation: none|partial|implemented` line outside code fences (`partial`/`implemented` also need an `Evidence:` line of comma-separated paths that exist); each `## Requirements` bullet starts `R-<spec file name>-<n>:` with IDs unique in the spec; every requirement ID is mapped to at least one test in `tests/PLAN.md`, and a PLAN.md ID that no spec declares is a problem. Declared `## Formats` artifacts are checked by readiness, not spec-lint (see `specs/formats.md`). Semantic duplicate/contradiction detection is later work. Wiring into `podge` is P2-5.
- Duplicate-symbol check to catch duplicate implementations from missed searches.
