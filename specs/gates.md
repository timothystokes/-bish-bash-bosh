# Spec: Gates (back-pressure, harness-enforced)
- Repo gate (`src/repo-gate.js`, `checkRepoGate`): refuse if the target repo is bish-bash-bosh itself. Used by the legacy agent-driven interview conversation (`src/bish-interview.js`) and `bish --reverse` (`src/bish-reverse.js`); neither `bash` nor `bosh` calls it (they operate only on `.bish-bash-bosh/*.md` files, never the target repo's own git history).
- Spec-lint (`src/spec-lint.js` `lintSpecs`, `bish-bash-bosh spec-lint`): structure only. Each `specs/*.md` is non-empty, starts with `# Spec: <name>`, has one top-level title (one decision per file), titles are unique, and (unless `lintSpecs(dir, {testPlan: false})`, which the legacy interview and readiness use) every spec is mapped in `tests/PLAN.md` (`parseTestPlan`, `src/bosh-test-plan-gate.js`: each line names a `specs/*.md` path or requirement ID, `R-<spec>-<n>`, and a `tests/*` path). The CLI `bish-bash-bosh spec-lint` always includes the mapping. Requirement traceability (X-1): each spec has an `Implementation: none|partial|implemented` line outside code fences (`partial`/`implemented` also need an `Evidence:` line of comma-separated paths that exist); each `## Requirements` bullet starts `R-<spec file name>-<n>:` with IDs unique in the spec; with the mapping on, every requirement ID is mapped to at least one test in `tests/PLAN.md`, and a PLAN.md ID that no spec declares is a problem. Declared `## Formats` artifacts are checked by readiness, not spec-lint (see `specs/formats.md`).
- `bish --reverse` (`src/bish-reverse.js`) enforces its own gates inline, not shared with any other mode: the working tree must be clean before the agent runs; afterward, staged changes outside `specs/`/`tests/` fail the round (work discarded); spec-lint (structure only) must pass; and the configured test command (`npm test` by default) must be green against the result. Any failure reverts the work (status `failed`).
- `bash` (the Plan Loop) and `bosh` (the Build Loop) have no gates of their own: per the owner's explicit minimalist design (`specs/modes.md`), each hands one item straight to the agent and ticks it once processed — no scope restriction, no test run, no spec-lint, no diff inspection. The agent is trusted within the conventions each loop's prompt states.
- There is no run-wide budget gate anywhere: `bish`'s Interview Loop ends on `paused` (EOF) or `ok` (every question answered); `bash`/`bosh` end on `ok` (every item processed) or a thrown error. `usage.json` (`{seconds}` only) is kept for visibility (`sumRunUsage`, `bish-bash-bosh status`/`tui`); the harness does not track tokens or cost on any adapter, and the owner monitors spend on the model backend.
