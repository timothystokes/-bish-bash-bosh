# Spec: Gates (back-pressure, harness-enforced)
- Repo gate (`src/shared/repo-gate.js`, `checkRepoGate`): refuse if the target repo is bish-bash-bosh itself. Used by `-bish --reverse` (`src/bish/bish-reverse-engineer.js`); neither `-bash` nor `-bosh` calls it (they operate only on `.bish-bash-bosh/*.md` files, never the target repo's own git history).
- `-bish --reverse` (`src/bish/bish-reverse-engineer.js`) enforces its own gates inline, not shared with any other mode: the working tree must be clean before the agent runs; afterward, staged changes other than `.bish-bash-bosh/specification.md` fail the round (work discarded); and `specification.md` must hold at least one well-formed `<n>. [ ] C: <constraint> B: <benefit>` item. Any failure reverts the work (status `failed`).
- `-bash` (the Plan Loop) and `-bosh` (the Build Loop) have no gates of their own: per the owner's explicit minimalist design (`specs/modes.md`), each hands one item straight to the agent and ticks it once processed — no scope restriction, no test run, no spec-lint, no diff inspection. The agent is trusted within the conventions each loop's prompt states.
- There is no run-wide budget gate anywhere: `-bish`'s Interview Loop ends on `paused` (EOF) or `ok` (every question answered); `-bash`/`-bosh` end on `ok` (every item processed) or a thrown error. `usage.json` (`{seconds}` only) is kept for visibility; the harness does not track tokens or cost on any adapter, and the owner monitors spend on the model backend.
