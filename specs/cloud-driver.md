# Spec: Cloud driver (AWS)
- **Status: future goal.** The current main goal is the Docker-based local implementation (`specs/loop.md`). This spec describes the later scaled-out solution; it is not a current requirement.
- Infrastructure as code: **AWS CDK**.
- AWS Step Functions loops over `podge`; each iteration is one Fargate Spot task (`RunTask.sync`) with a fresh context. Lambda is not used for iterations (15-minute cap, no persistent workspace); only for light steps (reading pointers).
- Git and run records are the source of truth. Execution context holds pointers only: commit SHA, iteration, last status, pause/stop flag; it must be rebuildable from git.
- Pause/steer/approval via `waitForTaskToken` or a control record read by a Choice state. There is no run-wide budget: the loop ends only on stop, done, a gated/failed step, or the per-execution iteration cap (successor).
- Kill switch: an external observer calls `StopExecution`. Verify `.sync` also stops the running ECS task.
- History limit (~25,000 events): run N iterations per execution, then start a successor execution with SHA and totals.
- Artifacts to S3, secrets from Secrets Manager. Spot interruption is tolerable: resume from the last commit.
- Local/cloud parity: the same container image and `podge` run in both.
- State machine is built by the pure `buildStateMachine(config)` (`src/state-machine.js`). Execution input is `{runId, executionIterations: 0}`; `$.pointers` is `{sha, iteration, status, paused, stop}`, re-read each loop by a light lambda. Decide order: stop, pause (wait + re-read), done, gated (fail), per-execution cap (successor).
- Pointer rebuilding (previously `rebuildPointers`, `src/podge-pointers.js`/`src/podge-read-pointers-handler.js`) was deleted along with `podge step`'s old build loop and never ported to `gepo`/`podge`'s new Plan/Build Loops: this spec's `$.pointers` contract (`sha`/`iteration`/`status` derived from git + run records) no longer has a matching local implementation to port from. Reconcile this when AWS is promoted, not before.
- CDK stack `HodgeStack` (`infra/stack.js`): ECR, S3 artifacts (versioned, private), EFS volume holding the project checkout (mounted at `/work` in the task and `/mnt/work` in the ReadPointers lambda, handler now missing — see above), Fargate task with Secrets Manager refs exposed as `HODGE_SECRET_<NAME>`, Fargate Spot cluster, state machine named `hodge-loop` (successor ARN built from the name). Synth is offline.
- Kill switch is the pure `stopRun({client, executionArn, controlFile?, cause?})` (`src/kill-switch.js`): sets `stop` in the control file first (so no successor execution starts), then calls `StopExecution` with error `KillSwitch`. A vanished execution returns `{stopped: false}`; other errors propagate. Live check that `.sync` stops the ECS task is P5-4b.
- Artifacts are synced by the pure `syncArtifacts({client, bucket, repoDir, runId})` (`src/artifacts.js`): `runs/<runId>/**` to the same S3 key, skipping files with an unchanged sha256 (idempotent). Promotion review is `requestPromotion({opener, runId, head, base, artifactsUri, sha})`: opens a PR from the project's branch, never merges, refuses head == base. Real clients live in `src/cloud-clients.js` (`createAwsCliS3Client` over `aws s3api`, sha256 in object metadata; `createGhPrOpener` over `gh pr create`), exposed as `hodgepodge sync --bucket --run-id [--repo <dir>]` and `hodgepodge promote --run-id --head --base --bucket [--sha] [--repo <dir>]` (defaults to the current directory).
