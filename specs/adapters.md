# Spec: Agent/model adapters
- Adapters v1: Copilot CLI, Claude Code, Codex, generic OpenAI-compatible HTTP.
- Common interface: take a prompt + working dir + limits (`{maxWallClockSeconds?}` only); return `{exitStatus, transcript, changedFiles}`. Adapters do not parse or report tokens or cost.
- Opt-in native session continuation: a caller that wants one continuing conversation (currently only the Interview Loop, `src/bish/bish-analyst-loop.js`) includes a `session` key on the request (`undefined` to start, or whatever the previous call returned, to continue); the response then also carries a `session` key to persist for the next call. A caller that never includes the `session` key at all (build/qa/reverse) gets the old, fully stateless behaviour with no new flags added and no `session` key in the result — this is a pure opt-in, checked via "does the request object have a `session` key", not "is it truthy". Each adapter owns its own token representation: Claude Code and Copilot CLI use a session/thread UUID (generated by the adapter on the first call), Codex captures the id the CLI assigns itself (the `thread_id` in its `thread.started` JSONL event) since it cannot be pre-assigned, and `openai-http` (no server-side session concept) uses the full prior `messages` array as its "session".
- A single configured **`adapter`/`model`** pair is used for every phase (interview, reverse, build, qa). Harness runtime logic never names a model or vendor. Exception: `-bish`'s automatic first-run setup (`src/shared/init.js` `ADAPTER_CHOICES`/`MODEL_CHOICES`) offers a numbered pick-list of known adapters and, for `copilot`, the model list fetched live from Copilot itself (`listModels`, falling back to just `auto` if the fetch fails); other adapters use a small static suggestion list that goes stale as vendors release models, so update it by hand when that happens. Nothing is enforced: any typed adapter/model string still works.
- Swapping agent or model is a config-only change.
- Every adapter passes the same contract test suite (fake agent fixtures; no network in unit tests).
- Cheapest start: CLI agents under existing subscriptions locally; pay-per-token small model for routine loops in cloud. Check vendor terms before unattended/cloud use of subscription-backed agents.
- Process-based adapters take injectable `command`/`prefixArgs`/`env` for fake-agent tests. `changedFiles` is derived from a before/after file-hash snapshot of cwd. Wall-clock limit kills the agent (exit 124); spawn failure is exit 127.
- Process-based adapters share `runProcessAgent` (`src/adapters/process.js`); each adapter only supplies args and an output parser. The Copilot adapter drops JSONL events flagged `"ephemeral":true` (`session.*`, `assistant.reasoning_delta`) from the live `--debug` output (the parsed transcript never contained them). Registry ids: `copilot`, `claude-code`.
- Opt-in live reasoning text: a caller that wants to show the agent's own "thinking" stream as it runs (currently only the Interview Loop) passes an `onReasoning` callback on the request; the Copilot adapter calls it with each `assistant.reasoning_delta` event's plain `deltaContent` text (never the surrounding JSON or any other ephemeral event), independently of whether `--debug`'s `onOutput` is also present. Adapters with no reasoning-stream concept simply never call it. `src/bish/bish-analyst-loop.js` wires this to its grey "Analyst thinking..." line so the text appears live, in the same colour, instead of a single static word.
- `openai-http` (any `/chat/completions` endpoint): no tools, so the model returns files as `<<<FILE path>>>`/`<<<END>>>` blocks that the adapter writes; paths outside cwd are rejected (exit 1). HTTP error => exit 2, unreachable => 127, wall-clock => 124. Endpoint and key from env `BISH_HTTP_BASE_URL` / `BISH_HTTP_API_KEY`; keys never live in config. Registry ids: `copilot`, `claude-code`, `codex`, `openai-http`.
- Adapter smoke check (`test/support/smoke.js`, `runSmoke`): asks an adapter to create `fizzbuzz.js` (FizzBuzz 1..15) and run it, then the harness re-runs the file and compares stdout; fails on non-zero exit, missing/extra files or wrong output. Test support for owner-run live checks; unit tests use the scripted adapter only.
